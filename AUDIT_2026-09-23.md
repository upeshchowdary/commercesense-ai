# sydon-1 — Read-only audit (2026-09-23)

Everything in this audit was read-only: no files were edited, no servers started or stopped, and no git changes made.

## What was tested

- **Python compile check** on all 15 backend modules: passes.
- **The whole API, run inside a test script** (FastAPI TestClient, so no server was started). All read endpoints work: 14 products, 9 flagged, and 404/422 errors come back correctly.
- **Signal detection accuracy:** 9 of 9 planted problems detected, 0 false alarms.
- **Frontend typecheck and lint:** the typecheck fails (issue 3) and the linter could not start.
- **Not tested:** anything that changes data or calls the paid APIs: `POST /signals/run` (wipes the signals table), `POST /decisions` (writes to the log), and `/research` / `/intelligence/run` (paid Gemini + Tavily calls).

## What was found (most serious first)

### Critical

1. **The grounding check doesn't verify anything.** `agent/schema.py:49` (`is_fabricated_risk`) only checks that a `source_snippet` exists. It never checks that the text actually appears in Agent 5's findings. The model can make up a quote and still be counted as grounded, which breaks standing rule 4.
2. **Search errors can become "evidence".** `agent/research_agent.py:133` and `:148` return error text such as `[search error: …]` as if it were a search result, with an empty URL. Not yet confirmed whether it gets filtered out later. If it doesn't, the Insight Agent can cite an error message as a source.
3. **The UI is still the default Vite starter page.** `frontend/src/App.tsx` has the "Count is 0" demo button, links to Vite and React docs, and placeholder social links. None of it does anything for this app, and the tab title is "frontend". There's no navigation, no LIVE/FAKE labelling and no approval button yet. Another agent may be building this, so check with it first.
   - The typecheck fails: `tsconfig.app.json:18` uses `baseUrl`, which TypeScript 6 rejects with error TS5101. `npm run build` will fail.
   - The linter (`npx oxlint`) couldn't start: "Could not determine Node.js install directory".

### API bugs

4. `/api/activity?limit=-1` quietly drops the oldest entry (it slices with `entries[:-1]`), and any limit value is accepted.
5. `/research` and `/intelligence/run` accept an empty or blank product name, which triggers paid Gemini + Tavily calls on nothing.
6. A missing `GEMINI_API_KEY`, or any agent failure, becomes a plain 500 error, so the UI would only show "Internal Server Error".
7. `/api/signals?severity=bogus` returns an empty list instead of a validation error. `category` on `/decisions` also accepts anything.
8. `POST /signals/run` wipes the signals table before re-running, with no protection. If two runs overlap, or someone loads the Evaluation page mid-run, the numbers are wrong.
9. `read_decisions` re-reads the whole log file on every call, and `/api/agents` calls it 6 times per request. One corrupted line in the log would break `/activity`, `/agents` and the product detail page.
10. `api/routers/intelligence.py` copies the orchestrator's logic instead of calling it, so the two can drift apart.
11. `api/routers/research.py` decides LIVE vs cache-hit with its own 6-hour window. If the research agent uses a different window, the LIVE/cached label is wrong (rule 5). Not yet checked which window the agent uses.
12. The evaluation only checks each product's expected signal. Extra, wrong signals on a product that also has a planted issue are never counted as false alarms.

### Loose ends

13. The DuckDuckGo fallback in `research_agent.py` breaks standing rule 2 (only Tavily and Gemini). `duckduckgo-search`, `pandas`, `faker` and `numpy` are in `requirements.txt` but nothing imports them.
14. Git state:
    - Deleting `app.py` and `ui/` isn't committed yet, and `api/` and `frontend/` aren't tracked yet.
    - There are 2 leftover `.kilo` worktrees (one marked prunable) that still hold the old `app.py`.
    - The notes say the main branch is `main`, but only `master` exists.
15. Phase 6 is still missing the LIVE/PLANNED table and the speaker script. The leftover starter images (`hero.png`, `react.svg`, `vite.svg`) and the "frontend" page title should go.
